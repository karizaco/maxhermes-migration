## Bucket 3 — Shell git push via python helper (2 crons)

These have a python helper that does the git push internally. The helper reads PAT from a local file. **For Cloud, the helper needs to read PAT from `${GITHUB_TOKEN}` env var** (which the secret tool provides at user scope).

| # | Cron | Notes |
|---|------|-------|
| 11 | Daily mavis-runtime backup | Helper scrubs Mavis state, exports, git push. Container of all Mavis customizations. |
| 21 | Daily agent-ops sync | Helper pulls/pushes agent-ops repo. Conflict-detection defensive sync. |

**Path:** Before staging these, install `GITHUB_TOKEN` via the secret tool (`secret create --name=GITHUB_TOKEN --value=<PAT>`). The python helpers need a small patch to read the env var instead of reading from a local file. Or, for simplicity, redesign to push via shell with the env var:

```
git -C /workspace/agent-ops add -A
git -C /workspace/agent-ops commit -m "sync $(date -I)"
git push https://x-access-token:${GITHUB_TOKEN}@github.com/karizaco/agent-ops.git main
```

Either way: needs the secret set first.

## Two-step migration plan

### Step 1 — Pilot (cron #18, Sun 02:00 ET)
Already staged at `cloud-prompts/01-weekly-mcp-health-check.md`. Reply tells us:
- What env vars the cron session sees
- Whether `/workspace/` and sandbox persist between cron sessions
- Confirms the secret tool works at user scope (will be set before any of the below)

### Step 2 — Bucket 1 staging (20 crons)
Stage as chat-delivery prompts that read skill specs from /workspace/ (or from a remote URL after we upload them), call MCPs, write to /workspace/, and reply with summary. No git push required. If `${GITHUB_TOKEN}` is set, optional push to minimax-cloud-outputs.

### Step 3 — Special: cron #24 X audit
Design before staging: where does the X export come from on Cloud?
- Option A: another cron generates the export and pushes to agent-ops repo (Cloud-friendly)
- Option B: you push the export manually weekly, cron reads from a Cloud-pinned location
- Option C: a different MCP-backed workflow (probably overkill)

### Step 4 — Bucket 3 staging (2 crons)
After `${GITHUB_TOKEN}` is set via secret tool. Patch python helpers or rewrite to use shell `git push` with the env var.

## Skill hosting decision (still pending)

Three options for how cron prompts access skill specs (SKILL.md files):

1. **Cloud-side copy.** Upload all 45 skills to /workspace/skills/ in the Cloud sandbox. Cron prompts read from there.
2. **Remote URL.** Push skills to `karizaco/agent-ops` `skills/` directory, reference via `raw.githubusercontent.com` URL. Works regardless of sandbox persistence.
3. **Both.** Cloud-side for fast reads, remote URL for shared authoring.

**Recommendation:** Option 2 (raw.githubusercontent.com) for now, since it works regardless of sandbox state and gives you version control over the skills. Switch to Option 1 once we know the sandbox is persistent.
